# Security Policy

## Supported Versions

Seka Kama Digital Twin currently provides security updates for the following versions:

| Version | Supported          |
| ------- | ------------------ |
| 2.x.x   | :white_check_mark: |
| 1.x.x   | :x:                |
| < 1.0   | :x:                |

## Reporting a Vulnerability

We take the security of Seka Kama very seriously, especially given the sensitive nature of conservation data and ecosystem modeling. 

If you discover a security vulnerability within Seka Kama, please do not disclose it publicly or file a public issue on GitHub. Instead, please follow our coordinated disclosure process:

1. **Email us directly:** Send an email to **security@sekakama.org** (or the project maintainer's primary contact).
2. **Provide Details:** Include as much information as possible in your report. Useful information includes:
   - The type of issue (e.g., SQL injection, XSS, insecure direct object reference)
   - Detailed steps to reproduce the issue
   - Evidence or proof of concept (PoC)
   - The impact of the vulnerability as you assess it
   - The version(s) of the application affected

### Response Timeline

- You should receive an acknowledgment of your report from the maintenance team within **48 hours**.
- We will provide an estimated timeline for the fix within **5 business days** of our acknowledgment.
- We will notify you when the vulnerability is patched, and we may ask you to confirm that the fix resolves the problem.

We appreciate your effort in helping to secure the Seka Kama platform and protect critical environmental and population intelligence.
